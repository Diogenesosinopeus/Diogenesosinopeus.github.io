# 联邦学习入门：数据留在本地之后

联邦学习让多个参与方在不直接汇集原始训练数据的情况下，共同训练一个模型。它适合数据分散在不同设备或机构、数据共享受限制的场景，但“原始数据不离开本地”并不等于天然安全。

## 一轮训练怎样进行

以横向联邦学习为例，各参与方拥有相同字段、不同用户的数据。一次典型训练轮次如下：

1. 协调方初始化全局模型，并向参与方发送当前参数。
2. 每个参与方用自己的本地样本训练若干步，得到本地模型更新。
3. 参与方上传更新，而不是上传原始样本。
4. 协调方聚合更新，形成新一轮全局模型，再开始下一轮。

最简单的 FedAvg 会按各参与方样本数量加权平均参数：

```text
new_model = Σ(client_sample_count × client_model) / Σ(client_sample_count)
```

这只是一个基线。参与方数据分布不一致、设备能力不同或上线时间不稳定时，训练过程可能更难收敛。

## 三个容易混淆的概念

- **横向联邦**：特征空间相似，样本主体不同。
- **纵向联邦**：样本主体重叠较多，特征空间不同。
- **联邦迁移学习**：样本和特征空间都不完全相同，需要迁移或对齐方法。

实际项目需要先确认数据关系，再决定协议和建模方式；“多方参与”本身不足以确定是哪一种路线。

## 隐私与工程边界

模型梯度或参数更新可能泄露训练信息，因此联邦学习需要结合威胁模型：谁可能作恶、能观察什么、能串通多少参与方。常见增强包括安全聚合、差分隐私和访问控制。它们会增加计算、通信或模型精度成本，需要在目标场景中评估。

工程上还要处理客户端掉线、更新校验、版本兼容、通信开销、恶意更新和审计记录。一个可用的联邦系统通常是训练协议、隐私保护和分布式系统工程的组合。
